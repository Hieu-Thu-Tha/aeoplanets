Lift-OS API Reference

The Lift-OS REST API gives you programmatic access to contacts, companies, deals, leads, and knowledge base articles in your workspace. Build integrations, sync data with external systems, and automate your revenue operations.
Base URL
https://lift-os.com/api/v1
Versioning

The API is versioned via the URL path. The current version is v1. All endpoints are prefixed with /api/v1/. When breaking changes are introduced, a new version will be released while the previous version remains available.
Response Format

All responses are JSON. Successful responses wrap data in a data field. List endpoints include a meta object with pagination info. All timestamps are ISO 8601 format.
json

{
  "data": { ... },
  "meta": {
    "next_cursor": 42,
    "has_more": true,
    "total": 150
  }
}

Authentication

Authenticate requests by including your API key in the X-API-Key header, or as a Bearer token in the Authorization header.
bash

# Using X-API-Key header
curl -H "X-API-Key: sk_live_your_api_key_here" \
  https://lift-os.com/api/v1/contacts

# Using Authorization header
curl -H "Authorization: Bearer sk_live_your_api_key_here" \
  https://lift-os.com/api/v1/contacts

Generating API Keys

API keys are created in Settings → API → Keys. Each key has configurable scopes (e.g. contacts:read, deals:write) that control which endpoints it can access. The full key is shown only once at creation — store it securely.
Security Best Practices

    Never expose API keys in client-side code or public repositories
    Use environment variables to store keys
    Grant only the minimum scopes required
    Rotate keys periodically and revoke unused keys
    Use separate keys for different integrations

Rate Limiting

API requests are rate limited to 1,000 requests per hour per API key (configurable). Rate limit information is included in every response via headers.
Header	Description
X-RateLimit-Limit	Maximum requests allowed per window
X-RateLimit-Remaining	Requests remaining in current window
X-RateLimit-Reset	Unix timestamp when the window resets
Retry-After	Seconds to wait before retrying (only on 429)

When rate limited, the API returns a 429 status:
json

{
  "error": {
    "code": "rate_limit_exceeded",
    "message": "Rate limit exceeded. Please retry after the specified time."
  }
}

Implement exponential backoff in your client. Respect the Retry-After header to determine when to retry.
Pagination

List endpoints use cursor-based pagination. Pass the cursor parameter with the ID of the last record from the previous page.
Parameter	Type	Required	Description
limit	integer	optional	Number of records per page (default 25, max 100)
cursor	integer	optional	ID of the last record from the previous page
bash

# First page
curl -H "X-API-Key: sk_live_..." "https://lift-os.com/api/v1/contacts?limit=10"

# Next page (use next_cursor from previous response)
curl -H "X-API-Key: sk_live_..." "https://lift-os.com/api/v1/contacts?limit=10&cursor=42"

The response meta object indicates if more records are available:
json

{
  "data": [...],
  "meta": {
    "next_cursor": 52,
    "has_more": true,
    "total": 150
  }
}

Filtering

Use query parameters to filter and sort results on list endpoints.
Parameter	Type	Required	Description
updated_after	ISO 8601	optional	Only return records updated after this timestamp
created_after	ISO 8601	optional	Only return records created after this timestamp
sort	string	optional	Field to sort by (e.g. createdAt, updatedAt, lastName)
order	string	optional	Sort direction: asc or desc (default: desc)
bash

# Get contacts updated in the last 24 hours, sorted by last name
curl -H "X-API-Key: sk_live_..." \
  "https://lift-os.com/api/v1/contacts?updated_after=2024-01-15T00:00:00Z&sort=lastName&order=asc"

Field Selection

Reduce payload size by requesting only the fields you need with the fields parameter. The id field is always included.
bash

curl -H "X-API-Key: sk_live_..." \
  "https://lift-os.com/api/v1/contacts?fields=id,email,firstName,lastName"

json

{
  "data": [
    { "id": 1, "email": "jane@example.com", "firstName": "Jane", "lastName": "Doe" },
    { "id": 2, "email": "john@example.com", "firstName": "John", "lastName": "Smith" }
  ],
  "meta": { "next_cursor": null, "has_more": false, "total": 2 }
}

Expanding Relations

Embed related objects in responses using the expand parameter. Multiple relations can be separated by commas.
Endpoint	Available Expansions
/contacts	company
/contacts/:id	company, deals
/companies/:id	contacts
/deals, /deals/:id	company, contacts, stage, pipeline
bash

curl -H "X-API-Key: sk_live_..." \
  "https://lift-os.com/api/v1/deals/5?expand=company,stage,pipeline"

Webhooks

Receive real-time notifications when data changes in your workspace. Configure webhook URLs via Settings → API → Webhooks or the internal API.
Supported Events
contact.createdcontact.updatedcontact.deletedcompany.createdcompany.updatedcompany.deleteddeal.createddeal.updateddeal.wondeal.lostdeal.stage_changedlead.createdlead.updatedlead.deleted
Payload Format

Each webhook delivery is a POST request with JSON body containing the event type, timestamp, and data. Two headers are included for verification and identification.
Header	Description
X-LiftOS-Signature	HMAC-SHA256 hex digest of the request body
X-LiftOS-Event	The event type (e.g. contact.created)
json

{
  "event": "contact.created",
  "timestamp": "2024-01-15T10:30:00.000Z",
  "data": {
    "id": 42,
    "firstName": "Jane",
    "lastName": "Doe",
    "email": "jane@example.com",
    "companyId": 7
  }
}

Signature Verification

Verify webhook signatures to ensure payloads are authentic. The signature is an HMAC-SHA256 digest of the raw request body using your webhook secret.
javascript

const crypto = require("crypto");

function verifyWebhookSignature(body, signature, secret) {
  const expected = crypto
    .createHmac("sha256", secret)
    .update(body)
    .digest("hex");
  return crypto.timingSafeEqual(
    Buffer.from(signature),
    Buffer.from(expected)
  );
}

Retry Policy

Failed deliveries are retried up to 3 times with exponential backoff (1s, 5s, 25s). After 10 consecutive failures, the webhook is automatically disabled. You can re-enable it in Settings.

Error Codes

When an error occurs, the API returns a JSON body with an error object.
json

{
  "error": {
    "code": "not_found",
    "message": "Contact not found"
  }
}

Code	Status	Description
unauthorized	401	Missing or invalid API key
forbidden	403	API key lacks required scope
not_found	404	Requested resource does not exist
validation_error	400	Request body failed validation (includes field info)
rate_limit_exceeded	429	Too many requests — retry after the specified time
internal_error	500	Unexpected server error

Validation errors may include a field property indicating which field caused the error.
json

{
  "error": {
    "code": "validation_error",
    "message": "Company name is required",
    "field": "name"
  }
}
