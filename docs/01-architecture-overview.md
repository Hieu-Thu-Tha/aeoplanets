# AEOSTARS — Architecture Overview

## 1. Introduction

AEOSTARS is an AI Representation & Visibility Intelligence platform that helps brands understand and improve their presence in responses generated by major Large Language Models (LLMs). It performs automated multi-model interrogations, assesses brand visibility, generates narrative perception profiles, identifies competitor positioning gaps, and delivers actionable content recommendations.

## 2. System Architecture

AEOSTARS follows a **Client-Server Single Page Application (SPA)** model with a **Modular Monolith** backend. All components are deployed as a single unit on managed cloud infrastructure.

## 3. Frontend Architecture

| Concern               | Technology                                         |
|------------------------|----------------------------------------------------|
| Framework              | React 18 with TypeScript                           |
| Build & Dev Server     | Vite                                               |
| Routing                | Wouter (lightweight SPA router)                    |
| Server State           | TanStack Query v5 (React Query)                    |
| Global UI State        | React Context (BrandContext, AuthContext)           |
| Design System          | shadcn/ui + Tailwind CSS                           |
| Theming                | Enterprise dark slate (custom CSS variables)       |
| Charts & Visualisation | Recharts                                           |
| Animations             | Framer Motion                                      |
| Icons                  | Lucide React                                       |
| Form Management        | React Hook Form + Zod validation                   |

### Key Frontend Modules

- **Dashboard** — AI Share of Voice, Commercial Recommendation Score, Category Authority, Core Web Vitals, competitor insights.
- **AI Perception Mirror** — Positioning summary, score gauges, brand weakness analysis, improvement suggestions.
- **Competitor AI Positioning Map** — Competitor frequency, missed prompts, competitive intelligence.
- **Semantic Coverage Gap Analysis** — Topic cluster visualisation, coverage gap actions.
- **Technical Brand Audit** — 12 structured AI-powered checks with findings and fixes.
- **Core Web Vitals** — Google PageSpeed data with competitor benchmarks and AI comparisons.
- **Actions Board (Kanban)** — Jira-style task management with AI-generated tickets.
- **Reports** — Executive Snapshot, Marketing Action, Competitive Intelligence (PDF).
- **Brand Settings** — Brand profile, competitor management, key terms management.
- **Team Management** — Role-based invitations with plan-based seat limits.
- **Change Monitoring** — Alert feed for significant visibility changes.

## 4. Backend Architecture

| Concern            | Technology                                          |
|--------------------|-----------------------------------------------------|
| Runtime            | Node.js                                             |
| Framework          | Express.js                                          |
| Language           | TypeScript (tsx in dev, esbuild bundle in production)|
| ORM                | Drizzle ORM                                         |
| Database           | PostgreSQL (Neon serverless)                        |
| Authentication     | Passport.js (LinkedIn OAuth + Local Email/Password) |
| Password Hashing   | Argon2id (via @node-rs/argon2)                      |
| Session Store      | PostgreSQL (connect-pg-simple)                      |
| CSRF Protection    | csurf                                               |
| Rate Limiting      | express-rate-limit                                  |
| Scheduling         | node-cron                                           |
| PDF Generation     | PDFKit                                              |
| SEO / SSR          | Custom SSR renderer with crawler detection          |

### Core Backend Services

1. **Assessment Engine** — Orchestrates multi-model AI scans. Manages batched LLM calls, coordinates parallel model queries, and triggers secondary analysis pipelines.

2. **LLM Runner** — Unified interface for querying OpenAI, Anthropic, and Google Gemini. All models are configured with live web search capabilities for real-time data.

3. **Perception Analyser** — Generates narrative perception profiles from visibility scan data. Produces positioning summaries, sentiment analysis, and improvement suggestions.

4. **Coverage Analyser** — Identifies semantic gaps in brand coverage across LLM responses. Maps topic clusters and recommends content actions.

5. **Readability Auditor** — Performs technical "machine readability" assessment of brand websites for AI crawler optimisation.

6. **Change Monitor** — Compares new scan results against historical data to generate alerts for significant visibility shifts.

7. **Ticket Generator** — Consolidates analysis findings into actionable task tickets using AI-powered prioritisation.

8. **Report Generator** — Produces formatted PDF reports (Executive, Marketing, Competitive Intelligence).

9. **Data Freshness Service** — Enforces a 7-day freshness threshold, ensuring all AI-generated data is current before report or ticket generation.

10. **Daily Scheduler** — Automated overnight visibility checks for all active brands and tracked terms.

## 5. Database Design

The PostgreSQL schema is organised into logical domains:

- **Identity & Access**: `users`, `team_invitations`, `team_members`
- **Brand Management**: `brands`, `tracked_terms`, `user_questions`
- **AI Analysis Results**: `visibility_runs`, `perception_profiles`, `coverage_gaps`, `readability_audits`
- **Workflow**: `action_tickets`, `action_comments`
- **Alerts**: `change_alerts`
- **Billing**: `subscriptions`, `subscription_addons`, `invoices`
- **Optimisation**: `ai_cache` (persistent cache to prevent redundant LLM calls)
- **Content**: `customer_reviews`, `news_articles`, `resource_library`
- **Reporting**: `reports`

## 6. Authentication & Authorisation

- **Primary**: LinkedIn OAuth 2.0 (OpenID Connect) for enterprise SSO.
- **Fallback**: Email/password with Argon2id hashing.
- **Sessions**: Server-side sessions stored in PostgreSQL with secure cookie configuration.
- **Roles**: Owner, Admin, Manager, Viewer — with granular permission checks.
- **Team Model**: Account owners invite team members; permissions and seat counts are enforced by subscription plan.
- **Trial System**: 30-day default with persisted per-account end dates and assigned Starter, Growth, or Accelerate entitlements. Provisioned trials use selected-plan limits, remain excluded from scheduled refreshes, and redirect to plan selection after server-enforced expiry.

## 7. Multi-Brand & Subscription Model

- **Multi-Brand Support**: Users manage multiple brand profiles from a single account with a global BrandContext and BrandSwitcher.
- **Plan Tiers**: Starter, Growth, Enterprise — each with defined limits for tracked terms, brands, competitors, team seats, reports, and feature access.
- **Add-on Packs**: Extra Brand, Competitor Pack, Key Terms Pack — stackable on any plan.
- **Key Terms Scaling**: Tracked term allowances scale proportionally with the number of brands (e.g., 10 terms per brand on Starter).
